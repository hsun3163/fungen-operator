# Evidence tests

Apply the complexity gate before and after every applicable test. No test or evidence mechanism may add more complexity than it removes. A failed or blocked test makes only the affected claim unverified.

Call evidence structural only when an external control prevents alteration; otherwise state the assurance actually provided.

## 1. Complexity gate

For every new file, production step, dependency, mechanism, option, intermediate, review, and departure from convention, state the observable trigger and greater complexity it removes. Remove duplicated mechanisms and anything retained only for agent history or compliance ceremony. Grow a runbook only when capability grows.

## 2. Regeneration test

Have an independent executor start from the retained revision and declared environment and follow the ordinary production path to regenerate each delivered output to the predeclared criterion. Use existing evidence for executor, start state, operation, and result. If native facilities cannot retain this without net complexity, label independent regeneration unverified instead of adding machinery.

## 3. Adoption test

Confirm that every retained output comes from a production execution whose immutable revision existed before the run. Confirm no production-path dependency is untracked or undeclared and every success claim cites production evidence rather than an experiment.

## 4. Clean-start test

Confirm the declared environment and inputs can be obtained or validated and the documented bounded operation passes from a project state matching the cited revision with no unrecorded load-bearing difference.

## 5. Diff test

Confirm every fact needed to operate the touched behavior is visible in retained project artifacts except declared external requirements. Confirm unrelated user changes were not absorbed.

## 6. Operation-identity test

Compare the ordinary documented operation with the operation that produced the cited evidence. Permit secret redaction and nonsemantic invocation differences only.

## 7. Recovery test

Apply only when interruption would repeat more work than the bounded verification workload. Interrupt a bounded run after a completed unit and repeat the documented operation. Confirm it finishes without corrupting state, duplicating effects, or repeating completed work beyond the declared recovery unit.

## 8. Repetition-safety test

Apply only when rerunning can duplicate, overwrite, or externally expose effects. Repeat the bounded operation and verify the predeclared idempotence or recovery criterion.

## 9. Failure-legibility test

Apply when the behavior accepts distinguishable inputs or work units and a bounded invalid case is safe. Send that case through the ordinary route and confirm existing evidence identifies the relevant failure context.

## 10. Orphan and path test

Confirm every retained or declared generated artifact has a practitioner-recognizable role and no retained production dependency points to an undeclared user-, session-, or temporary-state value.

## 11. Handoff test

Apply only when another practitioner needs continuity. Confirm the practitioner can find the operating path, requirements, evidence, fragile facts, and next action from ordinary artifacts without the transcript.
