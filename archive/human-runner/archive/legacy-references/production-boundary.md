# Production boundary

Read this when adoption or intervention boundaries matter. Apply the complexity gate before adding a response.

| Boundary failure | Human-path response | Evidence to inspect |
|---|---|---|
| Treat experimental success as verification | Promote the load-bearing change through ordinary artifacts and regenerate with the production operation | Retained revision plus native evidence from the later run |
| Copy, retype, paraphrase, summarize, convert, or freeze an experimental result | Classify it as adoption; declare its source and regenerate the retained result | Input or decision provenance and production output identity |
| Use an agent-only observation as a load-bearing fact | Repeat the practitioner-accessible source or operation; otherwise mark it nonreproducible | Human-accessible source and repeated observation |
| Add a recorder, manifest, gate, wrapper, status tool, logger, or monitor for assurance | Use existing program, engine, scheduler, platform, logs, tests, accounting, and history; narrow the claim if insufficient | Native records and explicitly unverified fact |
| Author, backfill, edit, or repair execution evidence | Preserve it and execute again for new evidence | Original incomplete record and later native record |
| Cite self-emitted success as independent proof | Treat it only as evidence; use external status or a predetermined check when independent proof is required | Platform status or externally captured check |
| Claim current status from historical logs | Obtain a timestamped live observation | Live query and observation time |
| Claim full production success from a bounded test | State only the bounded route and behavior verified | Bounded input, route identity, and criterion |
| Choose or weaken a criterion after seeing the result | Retain it before execution; obtain independent review when changed with implementation | Criterion history, review identity, and rerun |
| Force unrelated user changes into a revision | Isolate load-bearing state or stop | Working-state inspection and cited identity |
| Hide a state-changing diagnostic as temporary inspection | Obtain authority, name the target and effect, and use contemporaneous native evidence | Authorization, operation, target, and platform record |
| Record an intervention retrospectively | Record the first production intervention when it occurs | Native event record and decision entry |
| Put secret values into an exact command or record | Redact values while retaining secret names and sources | Redacted operation and source declaration |
| Call mutable agent-controlled history structural | State the actual assurance as reviewable policy or honor | Confirmed external control or explicit absence |
| Instantiate a standard artifact bundle | Add only a role this task needs, the project lacks, and a practitioner would keep | Audience, owner, lifecycle, and existing-artifact check |
| Add a script after manual work and imply it produced the result | Report manual origin; rely on the script only after it actually runs | Diff, timestamps, and later execution evidence |
| Call work complete because the command exited zero | Check expected final output and predeclared criterion | Output identity, status, and check |
| Bypass missing authority, credentials, scheduler access, data, or external requirements | Stop the affected operation and report the blocker and unverified scope | Read-only diagnostics and named external need |

The disqualifying pattern is laundering: making an experimental, hidden, or retrospective dependency appear to have come from the retained human path. Recover with a simple retained change followed by a real production execution, not more compliance machinery.
